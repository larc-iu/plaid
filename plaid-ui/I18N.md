# Translating the interface

Every string a person reads on screen goes through `plaid-ui/src/lib/i18n.js`.
Read the note at the top of that file first. This page is the working rules
and the French style.

## The rules

1. **The key is the English text.** `t('Save')`. English needs no catalog.
   The English a person sees must not change when a string is wrapped: the
   tests look for it.
2. **A message is a whole sentence**, in ICU MessageFormat. Never join
   translated pieces, and never translate a fragment such as "of" or "and".

   ```jsx
   // before
   <p>
     Document {i} of {n}
     {name ? `: ${name}` : ''}
   </p>;
   toast.success(`${countOf(n, 'entry')} imported`);
   // after
   <p>
     {name ? t('Document {i} of {n}: {name}', { i, n, name }) : t('Document {i} of {n}', { i, n })}
   </p>;
   toast.success(t('{n, plural, one {# entry} other {# entries}} imported', { n }));
   ```

   `countOf` and `plural` from `lib/plural.js` make English only. Replace
   each with a plural message, and a list joined by hand with
   `listOf(names)` from `i18n.js`. Inside `plural`, `#` is the number, formatted for the
   language. Two counts in one sentence are two plural blocks in one message.

3. **Markup inside a sentence** uses `tx`, with a tag per element:

   ```jsx
   tx('Delete <b>{name}</b> for good?', { name, b: (c) => <b>{c}</b> });
   ```

   A sentence is never split around a link or a bold word. Name the tag
   after its element (`strong`, `code`, `a`).

4. **Module-level constants** (a table of labels, an options list) are read
   before the language is known. Mark each message with `msg('Plain text')`
   and call `t()` where it is shown. Never call `t()` or `tx()` at module
   level. A parameter default such as `label = t('Method')` is fine: it is
   read when the function is called.
5. **The caller translates.** A component that shows a `label` prop shows it
   as given. The place that writes `label={t('Name')}` is the one that knows
   the text. A component never takes a bare noun to drop into its own
   sentence (`noun="guideline"`, `what="The draft"`): another language cannot
   make that agree. It takes the whole message, or the caller builds it.
6. **Braces, `#` and tags are ICU syntax.** A literal `{` or `}` in a message
   is written `'{'` and `'}'`. An apostrophe is otherwise ordinary in English
   ("Don't"), unless it comes straight before `{`, `}`, `<` or `#`: reword or
   use `’`.
7. **Never name a value** `count`, `context`, `lng`, `ns`, `defaultValue` or
   `replace`. Use `n`, `name`, `field`, `total`.
8. **What counts as whole.** A label in front of a finished sentence
   (`'{file}: {reason}'`) is fine, and so is a list of short counted clauses
   ("2 added, 1 kept"), each clause its own message. A translation may
   `select` on a value the English prints raw (a role, a scope) to choose
   its words, as long as it takes the same values.
9. **Never test a message's text in code** (`detail.startsWith('replaces ')`).
   Carry a `kind` beside it and test that.
10. **Same English, two meanings.** "Comment" is a noun on a tab and a verb
    on a button, and French says them differently. The first use stays
    `t('Comment')`. The second names its sense: `tc('verb', 'Comment')`,
    translated in the catalog under the key `"Comment [verb]"`. English shows
    the plain word either way. Senses are short lowercase words: `verb`,
    `noun`, `toast`, `job`, `list`.

## What is not translated

Mark each of these `// i18n-ignore` (or `{/* i18n-ignore */}` in JSX) with
the reason on the same line.

- **What goes into a file or into the project's data**: export column
  headers, tier names in an .eaf or TextGrid, a default field or preset name
  that is stored. Two people in two languages share that data.
- **Proper names and format names**: Plaid, ELAN, FLEx, CLDF, Praat, LaTeX,
  Markdown, a file extension, a key name such as Ctrl or Esc.
- **Text for developers**: `console.*`, an invariant error nobody is meant
  to see, a test id.
- **What the server or a model said**: shown as it came.
- **Another program's own words**: a FLEx menu path, an ELAN tier type. They
  stay as that program shows them, inside the translated sentence.

On a JSX attribute the mark is a `//` comment at the end of the attribute's
line. Text that goes both into a file and to the person (a note in an
export's README that is also a warning) needs two builders: the file's stays
English, the warning's is a message.

## Catalogs

`src/locales/fr/*.json` in plaid-ui and in each app, each a flat object of
English message to French. The files are split by area only so that people
can work at once. `plaid-ui/src/locales/fr/common.json` holds the words used
everywhere: do not translate those again elsewhere.

```
node plaid-ui/scripts/i18n-census.mjs plaid-igt/src/components/export        # what is left
node plaid-ui/scripts/i18n-census.mjs --keys plaid-igt/src/components/export  # the messages, as an empty catalog
```

`[sentence]` findings are a guess: a toast, a warning or an error a person
sees is wrapped, a string that is data or code is left alone. Every other
kind is wrapped or marked `i18n-ignore`.

A path whose work is finished goes in `plaid-ui/src/test/i18nDone.js`, and
`i18n.sources.test.js` then holds it to: nothing unwrapped, every message
translated, every translation taking the same values as its message.

## French

- **Register**: `vous`, never `tu`. Sober and plain, as the English is.
- **Buttons and menu items** are infinitives: Enregistrer, Annuler,
  Supprimer. A state in progress is a noun: Enregistrement…, Chargement…
- **Gender**: prefer wording that does not agree with the reader
  (« Connexion réussie » over « Vous êtes connecté »). Where a sentence must
  agree, use the masculine.
- **Sentence case**, as in English. French does not capitalise every word of
  a title.
- **Apostrophe** is always `’` (U+2019), never `'`: ICU reads the straight
  one as quoting.
- **Quotation marks** are `« »` with a no-break space inside (U+00A0):
  `« {name} »`.
- **Before `:`** a no-break space (U+00A0). **Before `?` `!`** a
  narrow no-break space (U+202F). No space before `.` `,` `…`.
- **Plurals**: French `one` covers 0 and 1. `{n, plural, one {# phrase}
other {# phrases}}`. Make adjectives and participles agree inside the
  plural block.
- **A list of names** as the subject makes the verb agree with something
  unknown. Turn the sentence so the list comes last: « Impossible de lire :
  {names}. »
- **No semicolons and no em dashes**, as in the English.
- Write these special characters as themselves in the JSON files.
